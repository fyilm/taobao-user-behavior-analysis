# 淘宝用户行为数据分析报告

> 数据来源：阿里天池「淘宝用户行为数据集」（UserBehavior.csv，约 1 亿条）
> 技术路线：DuckDB(SQL) / Pandas 数据清洗 → 漏斗分析 → RFM 用户分层 → Tableau 可视化 → 策略建议

---

## 一、项目概述

| 项 | 内容 |
|----|------|
| 数据规模 | 100,150,807 条行为记录 |
| 主体 | 987,994 用户、4,162,024 商品、9,439 类目 |
| 时间窗口 | 2017-11-25 ~ 2017-12-03（9 天完整数据） |
| 行为类型 | pv（浏览）、buy（购买）、cart（加购）、fav（收藏） |
| 工具链 | uv 依赖管理 · DuckDB + Pandas · Git 版本管理 |

**说明**：原始数据无表头、无金额字段。因此 RFM 中的 M（消费金额）以「购买次数」作为代理指标（见第四节假设说明）。

---

## 二、数据清洗

1. **缺失值与非法值**：5 个字段均无缺失，无非法行为类型。
2. **时间戳异常**：发现约 1.5 万条时间戳离群值（如 1902、1970、2018、2025、2036 年，占 0.015%），为 int32 边界溢出的脏数据，已剔除。
3. **完全重复行**：仅 49 条（约 0.00005%），影响可忽略。
4. **清洗后**：保留 2017-11-25 ~ 12-03 完整 9 天窗口，共 100,095,231 条。

行为占比：pv 89.6%、cart 5.5%、fav 2.9%、buy 2.0%。

---

## 三、漏斗分析

### 3.1 事件级漏斗（按行为次数）

> 口径：行为次数 = 一条记录算一次；「相对浏览的转化率」= 该环节次数 ÷ 浏览次数；「环节流失率」= 1 − 该转化率。

| 环节 | 行为次数 | 相对浏览的转化率 | 环节流失率 |
|------|---------|----------------|-----------|
| 浏览 pv | 89,660,688 | 100% | — |
| 加购/收藏 intent | 8,418,704 | 9.39% | **90.61%** |
| 购买 buy | 2,015,839 | 2.25% | **97.75%** |

关键路径转化：
- 浏览 → 加购：6.17%（**流失 93.83%**）
- 加购 → 购买：36.45%（**流失 63.55%**）
- 收藏 → 购买：69.79%（流失 30.21%）

**结论 1**：浏览→加购是最大的流失断层（流失 93.8%），绝大多数浏览没有产生任何意向行为；而一旦用户完成加购/收藏，购买转化显著提升，其中**收藏用户的购买意愿最强**（收藏→购买转化 69.8%，远高于加购的 36.5%）。

### 3.2 用户级漏斗（按去重用户）

| 环节 | 去重用户数 | 相对上一步转化率 |
|------|-----------|----------------|
| 浏览 | 984,105 | — |
| 加购 | 738,996 | 75.1% |
| 购买 | 672,404 | 68.0%（占浏览用户） |

**结论 2**：9 天内 **68% 的浏览用户最终发生了购买**（用户级），但事件级转化仅 2.25%。这说明「人有购买行为」≠「大部分浏览被转化」——用户浏览频次远高于购买频次，流量到成交的杠杆仍集中在浏览→加购/收藏这一环。

### 3.3 时间维度

- **日趋势**：12-01 加购率最高（36.4%），11-27 购买转化率最高（21.3%）；周末（12-02/03）流量最大（约 1370 万条/日）但购买转化率最低（约 18.5%）。
- **小时分布**：流量高峰在 **20:00–22:00**（21 点 PV 达 753 万），次高峰 9:00–16:00，凌晨 2:00–6:00 为低谷。

**结论 3**：周末流量高峰转化反而更低，存在「周末逛、平日买」特征；晚间为黄金转化窗口，营销活动应重点投放 20:00–22:00。

### 3.4 类目维度（TOP10 按购买用户数）

| 类目 | 浏览用户 | 购买用户 | 购买转化率 |
|------|---------|---------|-----------|
| 1464116 | 170,789 | 29,953 | 17.54% |
| 4159072 | 51,669 | 15,610 | **30.21%** |
| 2885642 | 148,345 | 27,118 | 18.28% |
| 1320293 | 343,972 | 14,903 | **4.33%** |
| 4756105 | 410,410 | 23,754 | **5.79%** |

**结论 4**：存在明显「高流量低转化」类目——类目 1320293、4756105 浏览用户数最高，但购买转化率仅 4%~6%；而类目 4159072 虽流量小却高达 30.2%。流量分配与转化效率严重不匹配。

## 四、RFM 用户价值分层

### 4.1 指标定义与假设

| 指标 | 定义 | 说明 |
|------|------|------|
| R（近度） | 距末次行为天数（基准 2017-12-03） | 越小越活跃 |
| F（频次） | 行为总次数 | 活跃度 |
| M（消费） | 购买次数 | **代理指标**：本数据无金额字段 |

评分方法：R/F/M 各按五分位打分（1–5），再按中位数二值化（高/低）划分经典 8 分群。

### 4.2 分群结果

> 列含义：用户占比 = 该群占总用户比例；平均频次 = 平均 F（9 天行为总次数）；平均购买次数 = 平均 M（购买次数，金额代理）。「流失」指 R 低，即最后一天（12-03）已无行为。

| 分群 | 用户占比 | 平均频次(F) | 平均购买次数(M) | 人群特征 |
|------|---------|-----------|---------------|---------|
| 重要价值客户 | 27.61% | 171.7 | 4.47 | 高活跃高购买，核心客群 |
| 一般价值客户 | 21.76% | 152.8 | 0.46 | 高频浏览、几乎不买 |
| 重要发展客户 | 16.53% | 44.8 | 3.32 | 低频但购买力强 |
| 一般发展客户 | 31.97% | 38.2 | 0.39 | 低频低购买，最大群体 |
| 重要保持客户 | 0.23% | 138.3 | 4.12 | 已流失的高价值客户 |
| 重要挽留客户 | 0.55% | 35.5 | 3.03 | 已流失的中价值客户 |
| 一般保持/挽留 | 1.35% | — | — | 低价值流失用户 |

**结论 5**：
1. **「一般价值客户」+「一般发展客户」合计 53.7%**——他们高频/活跃但购买次数极低（<0.5 次），是最大的转化洼地，也是增长潜力所在。
2. **「重要保持 + 重要挽留客户」仅 0.78%** 但人均购买 3~4 次、频次高，属于「流失的高价值用户」，召回价值极高。
3. 数据整体留存高（97.9% 用户在最后一天仍有行为），说明 9 天窗口内用户粘性强、流失样本偏少，R 维度区分度有限（这是短窗口数据的固有限制）。

## 五、策略建议

| 洞察 | 策略建议 |
|------|---------|
| 浏览→加购流失 93.8%，是最大断层 | 优化商品详情页与推荐位，加入「一键加购」「凑单推荐」等降低加购门槛；在浏览后 30 分钟内推送加购优惠券 |
| 收藏→购买转化 69.8%，远高于加购 | 强化「收藏」引导（收藏有礼、收藏降价提醒），把浏览用户先转化为收藏用户 |
| 高流量低转化类目（1320293 等仅 4%~6%） | 对低转化类目做流量重分配与选品/定价诊断，把资源导向高转化类目（4159072 达 30.2%） |
| 周末流量大但转化低、晚间 20:00–22:00 是高峰 | 周末用「活动/内容」承接流量，工作日投放「转化型」营销；黄金时段集中 push 与促销 |
| 「一般价值客户」高频不买（21.8%） | 针对高频浏览未购用户做「首单激励」「比价/优惠券」干预，推动首单破冰 |
| 「重要保持/挽留」高价值流失（人均 3~4 单） | 建立流失预警与召回：对 3 天未活跃的高价值用户推送专属权益召回 |
| 「重要价值客户」占 27.6% | 投入会员/专属服务维持忠诚度，防止向流失迁移 |

```
taobaouserbehavier/
├── data/raw/           # 原始 CSV（3.67GB，不进 git）
├── data/processed/     # 清洗后 parquet + 用户特征表（不进 git）
```

### 6.2 复现命令
```bash
uv sync                          # 安装依赖
uv run python scripts/run_all.py # 全流程：清洗→特征→漏斗→RFM
```

### 6.3 局限性
- 数据仅覆盖 9 天且无金额字段，RFM 的 M 用购买次数代理，结论需结合真实 GMV 数据验证。
- 用户级 68% 购买转化偏高，源于数据集为活跃用户样本（9 天内几乎人人有购买），不代表全站真实大盘转化。
